# git-graph Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring rabeeh-ta's git-graph into herdr-omni and grow it into one Git mod: a side panel with Changes and Graph tabs, a commit box, a branch picker, copyable hashes, and a full Git tab.

**Architecture:** `scripts/upstream.sh add` brings the upstream repo in as `./git-graph/`. New logic goes into new pure modules (`changes.js`, `branches.js`, `place.js`) tested with node against throwaway repos, and new view files (`changes-view.js`, `branch-picker.js`) that `graph.js` calls through small hooks, so upstream syncs conflict only on those lines. `main.js` picks side / full from `props.view`.

**Tech Stack:** Herdr gpui-kit mods (JS, `gpui-kit`, `gpui-base`, `herdr`); node `--test` + `node:assert`; git CLI.

**Spec:** `docs/superpowers/specs/2026-11-18-git-graph-design.md`

## Global Constraints

- Upstream: `https://github.com/rabeeh-ta/herdr-git-graph.git`, path `.`, branch `main`, folder `./git-graph/`, mod name stays `git-graph`.
- Keep `git-graph/LICENSE` (MIT). Ported git-panel code carries a header line: `Ported from git-panel (https://github.com/LaiqianDS/herdr-mods, Apache-2.0), itself from Herdr's shipped changes mod.`
- `graph.js` changes are hooks only (calls into new files); no rewrites of upstream functions beyond the named hooks.
- Tests: `cd git-graph && node --test tests/` (upstream's two scripts run under it too). `herdr-app check` on `git-graph/mods/git-graph` must pass.
- Tests create throwaway repos under `os.tmpdir()` with `GIT_CONFIG_GLOBAL=/dev/null`; never run write actions (commit, switch, discard, fetch, push) against a real project.
- No employer names, hosts or projects in committed files; neutral examples (`git.example.org`, `group/app`).
- Shared keys keep the `git-graph.` prefix. Tab name `Git`; tab icon `mods/git-graph/icons/graph.svg`.
- Mod rules: no stored `cx`; no `run`/`setShared`/`notify` in render.

## Review Focus

1. Paths with spaces and non-ASCII ("a b/ç.txt") stage, unstage, discard and diff correctly. Test in Task 2.
2. A repo with no commits yet: unstaging uses `rm --cached`, committing works, the Changes tab shows files. Test in Task 2.
3. A typed branch name that git rejects ("-x", "a b", "a..b") never runs `switch -c`. The picker shows no "Create" row for it. Test in Task 3.
4. Discard of mixed tracked and untracked files leaves staged changes untouched, and the confirm text names the counts. Test in Task 2.
5. The full tab, focused on itself, keeps the last terminal's repo, not the space folder. Test in Task 4.

### Task 2: Changes logic (`changes.js`)

**Files:**
- Modify `git.js` `parseStatus`: each entry also carries `xy` (the raw two letters). The existing fields are unchanged.
- Create `mods/git-graph/changes.js`.
- Test: `tests/changes.test.mjs`.

**Interfaces (produces):**
- `splitChanges(files) -> { staged: Change[], work: Change[] }`, where `Change = { path, s: "M"|"A"|"D"|"!", fresh: bool }`.
  - Untracked → work, `s:"A"`, `fresh:true`.
  - Conflict (`U`, `AA`, `DD`) → work, `s:"!"`.
  - Otherwise X≠" " goes to staged and Y≠" " goes to work, so a file can be in both.
- `changeCount(files) -> number`: unique paths.
- `fileTree(changes) -> Row[]`, where `Row = { kind:"dir"|"file", path, name, depth, change? }`.
  - Dirs come before files at each level, sorted by name.
  - Single-child dir chains are compressed ("src/shop").
- `stageArgs(paths) -> string[][]`: `[["add","--",...paths]]`.
- `stageAllArgs() -> [["add","-A"]]`.
- `unstageArgs(paths, hasHead)`: with HEAD `[["restore","--staged","--",...]]`, else `[["rm","--cached","-q","--",...]]`.
- `unstageAllArgs(hasHead)`: as above with `"."` (and `-r` for `rm`).
- `discardPlan(changes) -> { text, list: string[][] } | null`:
  - tracked → `restore --`, untracked → `clean -f --`, conflicts skipped.
  - `text` for one file: `Discard changes to <name>? This cannot be undone.` or `Delete untracked file <name>? This cannot be undone.`
  - `text` for several: `Discard <n> changed and delete <m> untracked files? This cannot be undone.`
- `commitPlan(title, body, stagedCount) -> string[][] | null`:
  - null when the title is blank;
  - `["commit","-m",title]`, plus `["-m",body]` when there's a body;
  - prefixed by `["add","-A"]` when `stagedCount === 0`.

- [ ] Tests run against a temp repo with a bare remote, as `graph.test.mjs` does, and apply the arg lists with `spawnSync("git", [...])`. Each assertion is one test:
  - `splitChanges`: a file modified in both index and worktree appears in both lists; untracked is `fresh`; a conflict gives `"!"`.
  - The path `a b/ç.txt` survives stage → unstage → discard (Review Focus 1).
  - No-HEAD repo: `unstageArgs([p], false)` empties the index, and `commitPlan("first","",0)` creates the first commit (Review Focus 2).
  - `discardPlan` on one tracked and one untracked file:
    - text `Discard 1 changed and delete 1 untracked files? This cannot be undone.`;
    - after applying it, a separately staged file is still staged (Review Focus 4).
  - `fileTree` of `src/shop/cart.js`, `src/shop/coupon.js`, `README.md` gives rows dir `src/shop` (depth 0), its two files (depth 1), then `README.md`.
  - `changeCount` counts a both-lists file once.
  - `commitPlan("  ","",1) === null`.
- [ ] Run, watch RED, implement, GREEN, full suite. Commit `git-graph: changes logic (stage, unstage, discard, commit, tree)`.

### Task 3: Branch logic (`branches.js`)

**Files:** Create `mods/git-graph/branches.js`; Test `tests/branches.test.mjs`.

**Interfaces (produces):**
- `BRANCH_REFS = ["for-each-ref","--format=%(refname)","refs/heads","refs/remotes"]`.
- `parseBranches(stdout, current) -> Branch[]`, where `Branch = { name, local, current }`.
  - Remote refs whose short name has a local branch are dropped, and so is `*/HEAD`.
  - Order: locals (current first), then remotes, each sorted by name.
- `filterBranches(list, query) -> Branch[]`: case-insensitive substring, max 200.
- `validBranchName(name) -> bool`: false for empty, a leading `-`, whitespace, `..`, `~^:?*[\`, a trailing `/` or `.lock`, or `@{`.
- `switchArgs(b)`: `["switch", name]` for local, `["switch","--track", name]` for remote.
- `createArgs(name) -> string[] | null`: `["switch","-c",name]` or null when invalid.

- [ ] Tests:
  - On a temp repo with `main`, `fix` and `origin/main`, `origin/fix`, `origin/only-remote`, `parseBranches(..., "main")` gives `main`(current), `fix`, `origin/only-remote`.
  - `filterBranches(list,"FI")` gives `fix`.
  - Applying `switchArgs` of the remote branch creates a tracking local branch.
  - `createArgs` is null for `-x`, `a b`, `a..b`, `x.lock` and `""` (Review Focus 3), and valid for `feature/login`.
- [ ] RED → implement → GREEN → suite. Commit `git-graph: branch list, filter, switch and create`.

### Task 4: Where it points and the Git tab (`place.js`)

**Files:** Create `mods/git-graph/place.js` (pure, no herdr import); Test `tests/place.test.mjs`.

**Interfaces (produces)**, modelled on `omni-forge/mods/omni-forge/views/locate.js`, taking snapshots `{ focused, panes, spaces }`:
- `MOD = "git-graph"`, `TAB_NAME = "Git"`, `MOD_ICON = "mods/git-graph/icons/graph.svg"`.
- `LAST_LOC = "git-graph.last-loc"`, `VIEW_KEY = "git-graph.side-tab"` (the "changes" or "graph" side tab, remembered).
- `terminalLoc(snap) -> { cwd, on } | null`:
  - the focused terminal's cwd;
  - `on` is the space's machine, or the `machine/` prefix of a layout terminal address;
  - null when the focus is a mod pane.
- `fallbackLoc(snap) -> { cwd, on } | null`: a terminal in the focused tab, then one in the space, then the space folder.
- `pickLoc(snap, last) -> { cwd, on } | null`: `terminalLoc ?? last ?? fallbackLoc`.
- `gitTabs(panes, spaces, spaceId) -> tabId[]`: the space's tabs holding only `git-graph` panes, in tab order.
- `sidePanelId(tree) -> string | null`: the id of the panel ancestor of the side git-graph block, as omni-forge's.
- `withModIcon(map) -> map | null`.

- [ ] Tests:
  - With focus on a git-graph mod pane in a tab of its own and `last = {cwd:"/w/feature"}`, `pickLoc` gives `/w/feature` (Review Focus 5).
  - With focus on a terminal in `/w/main`, it gives `/w/main`.
  - With no last and focus on a mod pane, it gives a terminal of the same tab, else the space folder.
  - `gitTabs` ignores a tab that mixes a terminal and git-graph.
  - `sidePanelId` finds `panel` in a trimmed copy of `main-graph`'s tree.
- [ ] RED → implement → GREEN → suite. Commit `git-graph: follow the last terminal, find Git tabs`.

### Task 5: Changes tab view

**Files:**
- Create `mods/git-graph/file-icons.js`: an exact copy of `~/.config/herdr-app/mods/better-changes/file-icons.js`.
- Create `mods/git-graph/changes-view.js`.
- Add icons `plus`, `minus`, `undo`, `list`, `list-tree`, `arrow-up`, `arrow-down`, `chevron-right`, `chevron-down` to `icons/`, copied from `~/.config/herdr-app/mods/git-panel/` (Lucide).
- Modify `graph.js`. Hooks:
  - the `refresh` status result feeds `this.changes.update(files, hasHead)`;
  - `render` asks `this.changes.render(...)` when the Changes tab or column shows;
  - Esc goes to `this.changes.escape()` first.

**Interfaces:**
- Consumes: `splitChanges`, `fileTree`, `changeCount`, `stageArgs` etc. (Task 2); `diffArgs`/`diffRows` from `git.js`; `followFileIcons`/`fileIcon`/`isLight` from `file-icons.js`.
- Produces: `class ChangesView` with:
  - `init(owner, cx)`, where `owner` gives `{ root, on, head, refreshNow(cx) }`;
  - `update(files, hasHead)`, `count()`, `render(t, mono)`, `escape() -> bool`.
  - Git commands run through `exec("git", args, { cwd: root, on })`, one list at a time. After a run it sets `setShared("git-graph.changed", Date.now())`, as `act.js` does.

**Behaviour (spec):**
- **Sections:** Staged (shown when non-empty; "Unstage all") and Unstaged ("Stage all", "Discard all"). Row hover shows +, − or ↶.
- **Discard:** goes through a confirm bar with `discardPlan().text`, Cancel and Discard.
- **List/tree toggle:** in the Unstaged header, remembered in `localStorage` (`tree`).
- **File icons:** shown when better-icons is present, else none.
- **Commit box:**
  - a folded "▸ Commit…" row; the fold is remembered in `localStorage` (`commitOpen`, default false);
  - title input (Enter commits) and a description textarea;
  - the button reads Commit, Commit all or Nothing to commit.
- **Clicking a file:** replaces the list with its diff and a "← Changes" link. Esc does the same.
- **Errors:** a dismissable red note.
- **Manygit list:** shows "Open a repository to see its changes".

- [ ] Verify:
  - `herdr-app check` passes and the suite is green.
  - On a scratch repo under `/tmp`: install with `sync.sh`, then take a screenshot (`perl -e 'alarm 25; exec @ARGV' herdr-app shot`) showing staged and unstaged files, the tree view and a diff.
- [ ] Commit `git-graph: Changes view (stage, discard, tree, diff, commit box)`.

### Task 6: Branch picker and copyable hash

**Files:**
- Create `mods/git-graph/branch-picker.js`.
- Modify `graph.js`:
  - the header's branch bubble gets `on_click` → `this.picker.toggle(cx)`;
  - `render` puts `this.picker.render(t)` under the header when open;
  - the `detailsPane` hash line becomes clickable.

**Interfaces:**
- Consumes: `BRANCH_REFS`, `parseBranches`, `filterBranches`, `switchArgs`, `createArgs`, `validBranchName` (Task 3).
- Produces: `class BranchPicker` with `init(owner, cx)`, `toggle(cx)`, `open`, `render(t)`, `escape() -> bool`.

**Behaviour:**
- **Search box:** placeholder `Switch to or create a branch`; Enter takes the exact match, else creates.
- **Rows:** current branch accented with "current"; remote branches muted.
- **"Create branch <q>" row:** first in the list, only when `validBranchName(q)` and no local branch has that name.
- **After switching:** the picker closes, `git-graph.changed` is set, and a failure goes to `notify` with level error.
- **Hash in the details strip:**
  - the full hash shows with a ⧉ glyph;
  - a click runs `cx.write_to_clipboard(hash)` and shows "Copied" for 1.5 s via a timer that clears a field (no work in render).
- [ ] Verify: check + suite, then a screenshot on the scratch repo showing the picker filtered, plus a manual copy test. Commit `git-graph: branch picker, click to copy the hash`.
